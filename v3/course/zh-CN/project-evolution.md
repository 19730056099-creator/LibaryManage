# 项目演变

## 最终问题与成熟能力

最终问题是：本地用户如何维护书目、知道当前可借副本、追踪借阅人，并在程序重启后恢复状态。成熟代码提供固定容量的 `Book`/`BorrowRecord` 数组、菜单分发、CRUD、子串搜索、借还库存变化、日期生成，以及两个管道符文本文件的读写。

## 最小可用起点

V0 是一个只在内存中工作的极小程序：放入一个 `Book`，允许用户添加并列出图书，退出后数据消失。它先制造“输入 → 状态 → 输出”的可见反馈，不提前引入文件、搜索、借阅或头文件重构。

## 演变总览

| 阶段 | 当前版本 | 上一版本价值 | 新压力 | 引入变化 |
|---|---|---|---|---|
| `milestone-01` | 菜单 + 静态数组的添加/列表 | V0 证明了最小状态变化 | 写死演示不能反复管理 | `Book`、计数器、add/list、菜单循环 |
| `milestone-02` | 内存 CRUD | M01 能新增并查看 | 重复 ID、错误记录无法修正或删除 | 唯一查找、部分更新、前移删除 |
| `milestone-03` | 图书文本持久化 | M02 能维护内存数据 | 退出后数据消失 | `fopen/fgets/fprintf/fclose`、管道符格式、`strtok` |
| `milestone-04` | 多字段子串搜索 | M03 能跨重启保留 | 书目变多后逐行查找太慢 | `strstr` 扫描 ID、书名、作者 |
| `milestone-05` | 借还与借阅记录 | M04 能快速找到图书 | 总量不等于可借量，还要知道借阅人 | `available`、`BorrowRecord`、日期、`borrows.txt` |
| `milestone-06` | 输入/文件/业务边界加固 | M05 的正常路径可用 | `atoi`、短行和未归还删除会产生隐性错误 | `strtol` 校验、坏行策略、不变量检查、删除策略 |

## 阶段因果链

### milestone-01

- **当前版本：** 可反复操作的菜单程序，把输入的图书放进静态数组并列出。
- **上一版本解决了什么：** V0 只显示一个简单结果；本阶段让结果来自用户且可以重复操作。
- **用户遇到的新问题：** 书目无法修正或移除，重复 ID 也会破坏后续查找。
- **本阶段引入什么：** `Book`、计数器、`do-while`/`switch` 菜单、add/list 和基础 ID 查找。
- **本阶段解决什么：** 最小入库和查看价值。
- **暂时延后：** CRUD 完整维护、文件、搜索、借还、严格输入校验。
- **下一阶段为什么会出现：** 用户需要修正和移除错误条目，因此需要 M02。

### milestone-02

- **当前版本：** 内存中的唯一 ID、部分更新和数组前移删除。
- **上一版本解决了什么：** M01 让用户能添加和查看书目。
- **用户遇到的新问题：** 重复或过期条目会降低列表可信度，中间删除还可能留下遍历空洞。
- **本阶段引入什么：** `findBookIndex`、部分更新、结构体赋值前移和计数器维护。
- **本阶段解决什么：** 一次运行内的基本维护，并保持有效元素连续。
- **暂时延后：** 重启恢复、搜索、借阅关系和坏文件恢复。
- **下一阶段为什么会出现：** 关闭程序会丢失内存，所以 M03 引入持久化。

### milestone-03

- **当前版本：** 图书数组能写入 `books.txt`，启动时能重新加载。
- **上一版本解决了什么：** M02 使内存中的书目可维护。
- **用户遇到的新问题：** 退出或第二天打开后状态不存在。
- **本阶段引入什么：** `fopen`/`fgets`/`fprintf`/`fclose`、管道符行和 `strtok`，成功变更后全量保存。
- **本阶段解决什么：** 图书数据跨重启存活。
- **暂时延后：** 借阅文件、坏行恢复、索引和高级搜索。
- **下一阶段为什么会出现：** 书目积累后，用户不应肉眼扫描整个列表，因此 M04 引入搜索。

### milestone-04

- **当前版本：** 可持久化的书目支持按 ID、书名或作者子串查找。
- **上一版本解决了什么：** M03 解决了跨重启保存。
- **用户遇到的新问题：** 目录变大后逐行阅读列表寻找目标成本太高。
- **本阶段引入什么：** `strstr`、found 标志和复用列表输出的搜索路径。
- **本阶段解决什么：** 用户只记得任一字段时仍能找到图书。
- **暂时延后：** 索引、排序、大小写归一化和借阅状态。
- **下一阶段为什么会出现：** 找到图书不代表还有可借副本，所以 M05 引入库存与记录。

### milestone-05

- **当前版本：** 两组数组和文件记录借还；借书减少 `available`，还书恢复它并标记记录。
- **上一版本解决了什么：** M04 让用户能快速找到书。
- **用户遇到的新问题：** 需要区分总馆藏、在架量和正在借阅的人，并阻止库存变负。
- **本阶段引入什么：** `BorrowRecord`、`findBorrowIndex`、`time/localtime`、`borrows.txt` 和库存不变量。
- **本阶段解决什么：** 正常借还与可追踪、可持久化的库存状态。
- **暂时延后：** 非数字输入、短行、越界字符串和未还书删除策略。
- **下一阶段为什么会出现：** 样例文件含字段不足的行，`atoi` 和当前解析器会静默接受坏数据，因此需要 M06。

### milestone-06

- **当前版本：** 在 M05 正常行为上增加输入、文件和关联状态的显式边界。
- **上一版本解决了什么：** M05 解决了正常借还与双文件保存。
- **用户遇到的新问题：** 非数字输入、截断文件和删除借出图书都可能污染状态或制造矛盾。
- **本阶段引入什么：** `strtol`/完整输入检查、字段数量/长度/数值检查、容量错误路径，以及“有未归还记录则拒绝删除”的明确策略。
- **本阶段解决什么：** 错误数据不会无声变成合法状态，库存与记录关系可解释。
- **暂时延后：** 数据库事务、并发、原子文件替换和网络部署。
- **下一阶段为什么会出现：** 本路线在参考项目边界处收束；继续开发应先重新评估压力，而不是无条件堆抽象。

## 最终架构如何形成

1. M01 先形成 UI 输入与内存状态。
2. M02 让 ID 查找、更新和删除拥有稳定语义。
3. M03 只有在重启丢数据的压力出现后才引入文件边界。
4. M04 复用线性遍历，不为小容量提前建立索引。
5. M05 在已有书目旁加入借阅记录，并用 `available` 连接两个对象。
6. M06 把 UI 输入边界、文件解析边界和删除策略显式化。

UI/业务/数据是帮助学习者追踪责任的教学边界；参考代码仍通过直接 include `.c` 文件组合，并没有正式的头文件 API。
